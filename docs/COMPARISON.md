# 各插件/Skill 共性与差异分析（Comprehensive Comparison）

> 基于对考公考编、考研、通用学习等 30+ 个开源插件/Skill 的深度调研。
> **结论：综合型插件应抓"共性引擎"，再按考试类型挂"适配层"，用户一套就能用所有场景。**

## 零、整合创新定位（本项目不是复制）

> **核心差异化**：本项目整合 30+ 开源项目的优点，优化融合，并**创新**出自己的亮点，用户无需装一堆插件。

| 亮点 | 说明 | 对比开源现状 |
|------|------|-------------|
| **全学段万能** | 小学/初中/高中/大学/考研/考公/四六级/职业资格/任何学科，一套系统 | 开源插件多按考试类型拆开，需装多个 |
| **K12 全学段适配** | 9大学科三层练习、三层错因分析、知识图谱诊断、艾宾浩斯复习、一题多解、口诀助记 | 整合 k12-smart-teacher 等 8 个 K12 项目 |
| **私教级全程辅助** | 找资料→分析资料→拆解资料→做题→复习→备考，全程 AI 一对一辅助 | 开源多偏单环节 |
| **离线刷题工具生成器** | 喂资料给 AI→自动出题→生成独立离线网页刷题软件（localStorage 持久化） | **创新**，开源少见 |
| **资源中心** | 官方平台（公告/考纲）+ 培训机构，可加自定义 | 开源少见 |
| **本地大模型算力** | 接入 dsh-our-free-model，独立部署不依赖 AI 应用 | 开源少有 |
| **三重形态** | 插件 + Skill + 独立软件，一个项目三处用 | 开源多单一形态 |

## 三、用户痛点（为什么需要综合型）

> **现状问题**：用户考公要装 kaogong-skill，考研要装 study-assistant，四六级要装 exam-practice，期末要装 StudyHub……装一堆插件，切换麻烦，状态不互通。

**综合型方案**：一套系统，按人群/阶段自动适配。

| 人群/阶段 | 自动启用的模块 |
|----------|---------------|
| 考公考编笔试 | 行测 + 申论 + 时政 + 报考 + 通用引擎 |
| 考公考编面试 | 面试 + 时政 + 通用引擎 |
| 考研初试 | 英语 + 政治 + 数学/专业课 + 通用引擎 |
| 四六级 | 听力 + 阅读 + 写作 + 翻译 + 通用引擎 |
| 期末/证书 | 任意学科 + 通用引擎 |
| 任何自学者 | 通用引擎（资料→知识→复习） |

## 四、综合型架构（Comprehensive Architecture）

```
│  资料解析 · 知识点 · 间隔复习 · 掌握度     │
│  错题本 · 刷题判分 · 学习计划 · 进度持久化 │
└──────────────────┬──────────────────────┘
                   │
        ┌──────────┴──────────┐
        ▼                     ▼
┌──────────────────┐  ┌──────────────────┐
│ 考试适配层（按需） │  │ 效率增强（通用）   │
│ 考公/考研/四六级   │  │ 真题分析·薄弱点    │
│ 期末/证书/面试    │  │ 进度可视化·打卡   │
└──────────────────┘  └──────────────────┘
```
